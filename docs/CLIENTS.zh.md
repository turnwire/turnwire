# 能力对等与代码归属

Web/PWA 消息输入框使用 Enter 发送、Shift+Enter 换行；Alt+Enter 保留插话发送。中文等输入法确认候选与按键长按不会触发发送。发送动作仍复用原有会话权限与忙碌状态检查。

本地 Codex bridge 的图片输入与推理档位由 DSH provider 配置声明，所有客户端仍以运行时能力为准。`config/dsh-deepseek.patch.yml` 按本机 Codex 模型目录声明现有模型能力，不为客户端新增模型或独立档位。Chat Completions 使用 `thinkingFormat: openai` 与 `supportsReasoningEffort: true`；`max` 保持发送 `max`，不映射为不同的 `ultra`。当前 DSH 无独立 `ultra` 选项。该配置不承诺完整思考过程输出或音视频输入；离线协议验证不替代真实上游验收。修改源码 overlay 不等于运行中的 DSH 已加载，生效前需核验实际 settings 与安全维护方式。

## 特定平台的安装细节

客户端可独立于执行主机选择。当前原生桌面实现面向 macOS 14+，构建需要 Xcode 16+ / Swift 6；在独立桌面仓库中执行 `cd ../turnwire-desktop && bash scripts/bundle.sh && open dist/Turnwire.app`。产物为 ad-hoc 签名，对外分发还需要 Developer ID 签名和 notarization。这些是该可选客户端的要求，不代表所有用户的执行主机都必须采用此平台。

当前后台主机安装器面向 Linux + systemd：在构建好的 release 中运行 `scripts/install-linux-host.sh`，先创建私有 DSH 环境文件（默认 `~/.config/turnwire/dsh.env.json`；支持 `TURNWIRE_CONFIG_HOME`、`XDG_CONFIG_HOME`、`TURNWIRE_DSH_ENV_FILE`）。该特定安装路径见[快速开始](QUICKSTART.zh.md)。npm 主机平台约束和已验证范围仍在 [npm 安装说明](NPM.zh.md) 中明确记录；产品介绍采用中立措辞不代表扩大兼容性承诺。

Web 设置不会向可编辑字段回填已保存的配对码或本机令牌。更换连接需重新输入凭据，取消保留当前连接。“在此浏览器记住连接”仅控制浏览器保存方式，不改变主机授权；切换立即将当前凭据在 localStorage 与 sessionStorage 之间移动。开启通知不会隐式开启长期保存凭据。CLI/原生的凭据存储机制及所有连接权限不变。

本机 CLI/TUI 和原生主机管理共用认证的 `/maintenance` 状态、开启、取消和整理操作。持有者令牌绑定的持久租约阻止 Turnwire 新任务提交，但保留取消任务、处理已有审批/问题。daemon 将本机管理写操作，以及异步部署、远程配置、直连监听和通知操作的完整生命周期纳入同一接纳计数。只有这些主机操作及托管运行时根会话、后代和队列都已知空闲才能就绪，未知时拒绝。重启恢复先取消属于旧运行时连接的审批，再检查维护租约，不因此恢复运行时工作。它不限制独立 DSH 客户端或无关会话。租约跨 daemon 重启保留，必须显式释放。释放后显式重新应用原远程配置，会根据期望配置与实际 transport 状态协调运行，包括恢复因租约而跳过的启动。相同请求不能重启正在连接、退避重试或服务中的 transport；就绪标签只是观测结果，不用于替代生命周期状态。`maintenance compact` 仅清理可重建导出缓存并执行 SQLite checkpoint/vacuum，永久保留 journal 序号和命令回执以维护恢复与幂等语义。

Core 的关闭生命周期与维护授权分离：关闭接纳后拒绝新 RPC/传输任务，已接纳的读取、变更和自动批准任务均跟踪至完成。主机清理允许在最终排空前结束；任务结束后才释放运行时订阅和存储。部署子进程直到实际退出才释放所有权，包括超时/取消后的信号升级；SSH 退出不等于远端安装已停止。Relay 推送后台错误由明确调用方接收并报告，不因此跳过数据库清理。

会话创建在分配 runtime 根之前，原子提交公开会话身份和持久创建意图。分配或模型设置失败返回可见的 error 状态会话，保留同一可恢复身份，不把孤立根藏在普通失败回执后；`session.resume` 可继续未完成创建。已建立的 DSH 根丢失或回放游标倒退时明确失败，不在旧历史/游标下静默重建新根。问题回答只有一个终态拥有者；队列前置条件在会话锁内检查；状态协调不能覆盖更新的运行时事件，未知或迟到审批回声不能复活已结束回合。

邀请消费以当前持久凭据作原子比较，异步加解密后重新检查当前授权；Relay/Direct 并发消费者不能从同一邀请安装不同密钥，同密钥的丢失确认恢复仍保持幂等。

必填 `RemoteStatus.health` 以 `unknown|ready|off|error` 分别报告 Relay 注册、隧道进程、公网可达性和设备确认。CLI/TUI 与原生本机管理显示同样字段。没有独立证据时公网可达性保持未知，不主动探测外部 URL，也不向已配对 PWA 授予主机管理权限。

产品 TypeScript 调用使用 SDK 的 `call(method, params)` 接口，由方法推导参数/结果；不存在 `rpc` 或 `callTyped` 方法。加密、端点校验和退避原语归入独立的 `@turnwire/wire` 包，服务端不再依赖客户端 SDK 总入口。记录导出由隔离 worker 使用独立只读 SQLite 连接读取持久化分片，生成私有的版本固定缓存。导出接纳数量、执行时间和记录大小均受限；daemon 不再在主事件循环拼接整条导出记录。关闭或整理存储时取消导出并释放读取连接。worker 启动失败会回滚请求接纳及临时资源；清理成功前始终保留资源所有权。清理失败向维护/关闭调用方报告并允许重试，不产生无人接收的后台 Promise 拒绝，也不让清理链永久失效。持有维护租约期间拒绝新的 `history.record` 导出，普通历史预览仍可读取。这些限制针对导出，不代表所有事件写入或预览分配都有相同内存上限。

PWA 和原生应用中的“收件箱”统一更名为 **审批中心**（英文 **Approvals**），CLI/TUI 帮助说明同步使用审批术语。现有 `inbox` 命令、`inbox.page` RPC、通知路由和持久记录保持不变。

本机安装使用 [XDG 目录](XDG.zh.md)，不检测或迁移旧布局。daemon 与 CLI 共享 Node-only 路径解析器；原生本机连接发现支持显式客户端/配置覆盖及 XDG 配置默认值。`TURNWIRE_STATE_HOME` 替代已移除的 `TURNWIRE_HOME`；config、data 和 cache 分别使用 `TURNWIRE_CONFIG_HOME`、`TURNWIRE_DATA_HOME`、`TURNWIRE_CACHE_HOME` 或各自的 XDG 默认值，保持分离。原生 Keychain/UserDefaults 已保存连接与远程协议不变。原生发现改动仍需 macOS 编译测试，当前 Linux 验证环境不具备该条件。

代审批按会话由 Core 持久保存，不是客户端本地偏好。共享命令与权威快照在重连或主机重启后保留明确选择，不依赖任何客户端保持打开。新会话默认关闭，手动关闭或归档取消；旧事件日志不恢复之前临时的授权。

[图片消息](IMAGES.zh.md)：PWA 支持选图/粘贴、预处理预览、移除和明确发送；CLI/TUI 通过 SDK 使用 `send <session> [text] --image <path...>`。原生代码包含本地图片选择和引用读取，macOS 编译与实际 UI 验证仍待完成。runtime 的 `imageInput` 仅表示传输能力，当前模型可能拒绝图片。历史和文本导出保留引用元数据，不内嵌字节；图片功能不增加主机管理权限。

PWA 底部子代理列表仅包含最近一个已开始的用户轮次中、通过启动回执确认身份的子代理及其后代；排队和 steer 消息不另开轮次。新的用户轮次会清空旧列表，历史详情仍保留在原消息位置。若分页历史未载入轮次边界或启动回执，先不猜测归属，可加载更早记录。DSH 的 inactive 包含已释放运行实例的持久历史条目，不代表残留 OS 进程；不能因该标记就杀进程或删除历史。

[移动端样式评估](MOBILE-AUDIT.zh.md) 记录了窄屏工具栏、短视口和点击区域修复、浏览器覆盖及真机/焦点/滚动限制。代审批仍在现有输入框工具栏里，停止按钮紧凑显示，模型名优先收缩让位于操作按钮，长工作目录优先保留末级部分。

CLI、交互式终端（`turnwire tui`）和原生桌面都是同一个 Turnwire 主机的客户端。在相同的连接权限下，它们必须支持相同的产品操作，并观察到相同的状态。UI 机制可以不同：工作区路径 vs NSOpenPanel、终端二维码 vs NSImage，或打印链接 vs 剪贴板按钮。

## 上下文占用与插话

会话可选的 `context` 由运行时提供，经快照和 `session.updated` 分发；`contextWindow`、最近一次请求的 `pressureTokens`、下一次请求估算的 `projectedTokens` 均可独立缺失。客户端不得从模型名推断窗口、混淆累计 token 消耗与当前占用，或把缺失值显示成零。优先展示估算值并明确标记；只有窗口已知且为正数才显示百分比。Web、CLI/TUI 和原生会话展示读取相同字段。原生源代码与测试仍需 macOS 执行，不能以 Linux 检查替代原生 UI 验证。

插话表示在当前回合的下一执行步骤边界交给模型，不会中断正在生成的响应或工具，也不是给未来回合队列重新排序。Web 区分普通 `next-turn` 排队和已转为 `next-step`、等待消费的插话，保留运行时目标字段，不对已插话消息重复提供插话操作。长步骤会延迟消费；操作被接纳不代表模型已经按消息行动。待处理队列的编辑、删除、转插话控件目前仍仅在 Web 提供；CLI/TUI 和原生支持发送插话消息，但待处理队列控件属于既有能力对等缺口，本次不宣称已覆盖。

## 代码归属

| 层次 | 职责 | 位置 |
| --- | --- | --- |
| 共享 protocol | 请求、结果、校验、事件与远程状态 | `packages/protocol` |
| 领域 | 会话、runtime 路由、审批、回执与事件持久化 | `packages/core` |
| Host 服务 | 远程模式状态、已保存设置、配对与传输生命周期 | `apps/daemon` |
| Relay | 经过认证的 host/device 路由、共享流量上限与公网 PWA 服务 | `apps/relay` |
| 服务器部署 | 可移植安装器、SSH 传输与文件/配置回滚 | `apps/deployer`；daemon 拥有任务与私有状态 |
| Provider 适配器 | 组件安装、provider 网络与子进程生命周期 | `apps/daemon/src/providers` |
| 共享 wire 原语 | 会话加密、配对/端点校验与重试 | `packages/wire` |
| TypeScript 客户端传输 | 本地 RPC、类型化管理与加密远程连接 | `packages/sdk` |
| 终端呈现 | CLI 与 TUI 共用的单一命令注册表、prompt 与二维码渲染 | `apps/cli/src/program.ts`, `terminal.ts` |
| 原生呈现 | Swift 线上模型、API 客户端、SwiftUI 状态与控件 | 同级 `turnwire-desktop` |

`RemoteController` 从 daemon 入口点接收 provider 注册表。localhost.run、cpolar 和 Cloudflare 适配器拥有组件安装与前台进程生命周期。自托管 Relay 不依赖隧道。provider 选项与指引随远程状态一起返回，并由终端和原生客户端展示。cpolar 凭据保留在 daemon 私有状态中；只有 `hasCpolarToken` 会返回给客户端。

TUI 目前提供面向行的交互式命令界面，包括交互式 Relay 设置。它复用整个 CLI 命令注册表；它不是独立的全屏渲染器。`attach` 进入共享会话的对话；Ctrl+C 返回命令界面，且不会停止 Agent。输入被解析为参数，不经过 shell 求值。

| 回答 Agent 正在等的问题 | `questions`、`answer <question> '标签' [--text …]` | 相同命令 | 尚未支持 —— 见下方说明 |

主机管理使用经过认证的本地 `/remote` 和 `/devices`。已配对手机或远程 CLI 可以操作会话和审批，但不能更改主机设置或配对更多设备。这是由 daemon 强制执行的连接权限边界，而不是缺失的 UI 功能。PWA 目前承担这一已配对手机角色。

子代理视图（`subagent.list`、`subagent.history`）显示真实执行消息、工具输入和结果，不再只有可选的计划。PWA 和 CLI/交互终端已接入；原生客户端已实现，但仍需 macOS 编译和实机验证。排队控制、审批委托（`session.autoApprove`）、回答问题（`question.answer`）仍有上表列出的桌面端缺口。被委托的会话是唯一"批准之前没有人看过"的地方；而问题永远不会被委托，因为它没有安全的默认答案。问题显示在 Agent 提问的位置、作为对话的一部分，而不是页面别处的某个控件：选项和输入文字都先作为草稿，整张卡片只有一个提交按钮，必须每题都有答案才能提交，不能由某一行静默结束尚未回答的其他题。Enter 遵循相同规则，输入法组词时不提交。请求中或断线时控件保留并禁用，不卸载输入框。回答之后卡片留在记录里，导出的记录和 `turnwire history` 打印的也是它。这是 PWA 的呈现校验，共享回答协议和 CLI 的显式回答命令不变。已结束回合按时间保留所有助手正文，不再假定最后一条消息总结了前文；工具详情仍可单独展开，委派工具已返回也不代表后台子代理已完成。问题的选项是一列，而不是一排各自居中的标签：每个选项都从同一条左边缘开始、宽度一致，说明文字挂在标签下方——参差不齐的标签正是让选项列表看起来像坏掉的原因。卡片里的任何内容都不许把卡片撑宽：用户手写的回答要在原处完整显示，而路径、密钥、摘要这类没有任何断行机会的值要在卡片内换行，而不是伸出卡片边缘；能被左右拖动的卡片，和能被左右拖动的排队提示是同一种缺陷。子代理列表同理：一行本身就是打开该子代理的控件，展开后显示的计划是三列表格——标记、状态、步骤本身——每一行的三列都对齐。列表优先展示运行中的子代理，也保留未运行子代理自己的执行记录入口；展开一行会显示运行时对该子代理自身的描述（能否继续、位于哪一层）以及它上报的计划，没有上报计划的会直接说明，而不是显示一张空表。`turnwire agents` 会一次打印所有子代理的同样内容，因此终端不需要第二条命令才能看到计划。

PWA 保留两个子代理入口：输入框上方的运行区域，以及消息流中委派工具实际位置的持久详情入口。启动调用不再埋进其他连续工具的折叠组。成功的可继续后台启动回执用精确的持久 ID 匹配根会话的直接子级目录，同名和乱序返回都不影响位置；运行区消失后，未运行子代理仍能在原处查看。这是 CLI/TUI 与原生客户端已有 `subagent.history` 的另一种呈现，不增加控制权限。当前 DSH 历史不提供前台子代理身份或旧后台任务到子代理的映射，这些调用仍显示为普通启动工具，不猜测关联；尚未返回或失败的调用也保留，工具返回不等于子代理完成。

PWA 目录选择器支持在当前目录中「新建文件夹」，成功后进入新目录，只有点击「使用此文件夹」才确认会话工作目录。取消或创建失败保留此前选择。CLI/TUI 使用 `dirs [path] --mkdir <name>` 调用相同的 `workspace.mkdir`；省略路径时使用主机家目录。原生本地 NSOpenPanel 也启用了新建文件夹（macOS 验证待完成）。

两个"文件夹选择器"并不是一回事：手机通过 `workspace.list` 走的是主机自己的目录，这也是远程连接下唯一有意义的选择器；`turnwire dirs` 让终端拿到同一份列表。桌面端的面板选的是 Mac 上的文件夹，因此只有桌面连的是本机 daemon 时才和主机一致；远程连接的桌面端仍然需要手动输入路径。

部署通过 `/deployment` 使用同一套本地权限边界。客户端提交 runtime 配置并显示共享的异步状态；它们自身从不运行 SSH 或安装服务。daemon 拥有该任务、持久化私有配置、从子进程中剥离模型凭据，并通过 `RemoteController` 连接已安装的 Relay。服务器地址、登录账号和 key 路径是必需的 runtime 输入。可选的高级设置可通过每个客户端中的共享 JSON 配置以及原生高级字段使用。关闭客户端不会中断任务；daemon 中断会被显式报告以便恢复。

## 变更验收

会话管理入口位于会话列表，不放在对话页：PWA 使用每行「更多」菜单，原生桌面使用侧栏会话行的「更多」/右键菜单。重命名、归档/还原，以及原生已有的导出、复制、在 Finder 显示等操作针对该行，不切换当前会话或清空对话草稿。客户端操作的成功、失败和清理回调均绑定连接代际与请求拥有者，模型目录缓存绑定主机；无版本的动作回包不能替换已由新事件推进的实体。历史投影以稳定 `originSeq` 维护分页/导出身份，以可选 `displaySeq` 表示实际执行顺序：排队转运行时只移动一次，后续编辑保留位置；原生和 TypeScript reducer 一致地补丁更新用户消息，不把 `message.updated` 当作新消息类型。

菜单展开由列表统一协调，鼠标与键盘操作都只能同时打开一行。管理结果归属于目标会话及操作，不复用当前选中对话的运行时错误通道；失败显示在管理界面中，迟到回包不能关闭其他会话的菜单。归档对话只显示只读提示，不提供内联还原按钮。发送、停止、审批和恢复执行仍属于对话交互；CLI/TUI 保留显式管理命令。

重命名和归档是由 Core 元数据与 journal 事件支撑的 protocol 命令。归档会保留历史、拒绝活动会话/待处理审批，并在恢复前阻止 resume/send。本地与加密客户端通过同一事件流看到变更。原生 Markdown 渲染、按会话草稿、结果视图、内容搜索和审批中心都是对共享记录的呈现。共享投影会丢弃不携带文本的 assistant 消息，因此在每个客户端中，仅由工具调用构成的回合会显示其工具块，而不是空气泡。回合运行期间发送的 prompt 默认排在它之后；当客户端要求时（`mode: steer`），也可以改为插话引导该回合；被记录的消息在等待期间携带 `queued` 或 `steer`，而主机会记录等待中的提示真正开始执行的时刻，因此每个客户端既能标注实际发生了哪一种，也能把它放进真正运行它的那个回合。只有 `stop` 会取消回合，且它从不注入文本。还在排队的提示位于输入框上方，编辑、取消、插队三个操作只出现在它自己那一行；这一行就是提示文本加这三个按钮，因此按钮保持自己的尺寸，文本被截成一行省略号，全文仍留在该行上供悬停或长按查看。这些操作只属于还能收回的提示：一旦 runtime 开始执行，这一行会进入真正运行它的回合，此时取消会明确回答「已经开始」，而不是把模型正在回答的消息抹掉。再长的排队提示也不能把盒子撑宽：在手机上，这种失败的表现就是盒子可以被左右拖动；正在运行的子代理列表里的标签同理。

手机/PWA 把 assistant 事件文本渲染为 CommonMark + GFM（标题、列表、引用、行内/围栏代码、表格、任务列表、链接和脚注）。代码和宽表格在各自区域内滚动；代码可以复制。未完成的流式围栏会按代码渲染，并在完成后更新。该渲染器属于 web 呈现层：它不改变事件文本、CLI 历史/导出、原生渲染或共享会话规则。用户输入和原始工具结果保留其字面表示。原始 HTML 保持惰性，图像引用按既有图像策略显示为显式链接。原生应用已有自己的 Markdown 呈现；终端可以保留源格式。PWA 也选择会话模型与 reasoning 强度，入口是输入框中的一个 chip，选项就地贴在它旁边展开，而不是放在会话标题里、也不是作为输入框上方的一块面板：手机打开会话时会固定在最新消息上，因此可滚动区域内的控件恰好会在最需要它的地方跑到屏幕外，常驻展开的一行会让输入框失去键盘所需的高度，而把输入框往下推的面板会让它从正要打字的手指下面移走。面板直接按 provider 分组列出 runtime 模型，点选即可，没有搜索输入框和第二步确认。打开时聚焦面板而不是文本框，不会因模型搜索而唤起手机键盘。当前模型带勾选标记（`aria-pressed="true"`），会话尚未显式选择时也标出 runtime 默认模型；按钮的 `data-provider` 与 `data-model` 值就是 runtime ID。对话框英文标签为“Model”，可滚动列表使用 `.model-list`。点击立即提交；请求等待期间锁定模型和强度控件，防止重复提交。成功后收起面板；失败则保持展开，在面板内显示错误并允许重试。点面板外面或按 Esc 会收起它，Esc 还会把焦点还给模型 chip。打开面板时会重新拉取模型目录，主机报告模型不可用时也会再拉一次——因为页面开着的时候，某条 route 可能增减模型：已经从端点上消失的 id 不该继续留在屏幕上可选。模型、provider 分组与 reasoning 强度全部来自 runtime 目录，客户端不维护另一份列表。成功后重新打开，会显示已选模型；如果该模型声明了强度，则显示“Reasoning effort”下拉框，使用主机解析后的值以及 runtime 声明的选项和默认值。换模型时，只有当新模型自己也声明了原 reasoning 强度，才会沿用它；否则由主机解析默认值，没有 reasoning 强度的模型不显示强度控件。工具调用遵循同样的规则：折叠的行直接写出这个调用在做什么——它跑的命令、它读写的文件、它委派的任务——超出宽度用省略号截断，悬停或长按可以看到全文，因此没人需要为了弄清一条命令是什么而展开它。连续的工具调用在运行期间只占一行，显示最新的一条；最后一次返回后变成这次运行的汇总（「shell ×3 · 已返回」）。展开一次运行不会再画出框套框：调用在一条细线下面缩进，唯一的框是真正被打开的那一个调用。回合结束后仍保留所有已收到的正文，不再将最后一条消息之前的内容自动折叠为过程；只有工具详情单独折叠，子代理启动入口始终位于消息流的原始位置。

行为特性应从其所属的共享层开始，然后通过所有适用的客户端暴露。检查来自一个客户端的命令是否能在另一个客户端中可见，且无需客户端特定的重启或数据库。对校验、授权和生命周期影响使用有意义的集成覆盖。Swift 实机测试提供跨语言契约检查。纯 UI 的便利功能可以留在其平台原生侧。

不得把 provider 可用性与主机注册混为一谈。Relay 连接可用并不能证明每个手机网络都能解析并到达其公网 origin。Cloudflare Quick Tunnel 是可选的开发用访问方式；为中国大陆选择固定 Relay 时，请使用部署指南。

手机始终显示连接状态，包括窄屏：连接中、未验证或已断开时是连接栏——这些状态需要解释；一旦验证通过，就只剩一条细线，显示主机、往返延迟，点击可重新验证。连接失败所抱怨的问题一旦被重新连接解决，横幅会自行消失；而作为对用户操作的答复的错误则保留，直到被关闭或被新的结果取代。`RemoteClient` 只有在与预期 Mac 完成一次加密 nonce 往返后才发布健康状态。它在前台时每 15 秒探测一次，5 秒后超时；回到前台时先确认并复用仍然持有的 socket，而不是重建——只有确实已经不存在的 socket 才会重建，因此切标签页不再等于重连。v2 会话会等待主机对最终确认的确认。Mac 在把设备标记为已连接之前，需要对其自身新发出的 challenge 收到加密确认；如果没有再次确认，其肯定状态会在 25 秒后过期。仅凭 Relay 就绪和已保存的配对凭据无法产生肯定的连接状态。这些是近期的观察结果，不保证未来的连通性或后台 iOS 执行。

从游标 0 开始的显式事件订阅可能包含数千个加密事件。Relay 对手机施加其消息入口速率限制，而经过认证的主机可以重放该历史而不触发手机限制。帧大小与慢消费者缓冲上限对两种角色仍然强制执行。这是所有远程客户端共享的传输行为；不需要客户端特定的绕过方案或线上格式变更。该回归测试演练 4,000 个真实加密事件、健康确认以及随后的快照请求，并附带一项独立的手机洪泛拒绝检查。

### 按需会话历史

`history.page` 是一个共享的只读 Core RPC，供 SDK、CLI/TUI、Swift 和手机/PWA 使用。它按每条记录的首个事件序号向后分页（`before` 为排他），默认返回 40 条完整记录，并返回 `events`、`cursor`、`hasMore`、`nextBefore`。存储在保持原始 journal 不变的同时，维护消息、工具输入/结果对、审批请求/决议和错误的持久投影。Store 仅接受空数据库或当前最终 schema；旧版、无版本或格式损坏的数据库返回 `UNSUPPORTED_STORAGE`，不迁移或从 journal 回填。应使用独立的空数据库，而非修改旧库。传输页面限制为 512 KiB；超大文本事件以明确的 64 KiB 预览返回，带有 `truncation` 元数据和可见截断说明。完整内容仍保留在主机。显式完整导出使用 `history.record` 按会话和记录版本分块读取；SDK/CLI/TUI 与 Swift 导出会补全预览，交互式阅读不会自动下载完整大正文。单记录组装限制 64 MiB，超过时明确失败；记录变化最多重试三次。Swift 目前只有静态检查和新增测试代码，仍需 macOS 编译及真实原生联调确认。

打开会话会立即加载最近一页，而不是从头加载数千个 token 片段。Web 滚动到顶部自动加载下一有界页，不再显示加载按钮，也不再限制整个会话只能自动加载固定页数；初次进入停留在最近消息，失败后等待再次向上滚动重试，切换会话后的旧响应会丢弃。Swift 保留加载更早记录控件；CLI/TUI 显示下一条 `history --before` 命令。搜索和显示的记录数只覆盖已加载记录。完整导出是显式操作，仍会访问每一页（`export`、原生“导出完整会话…”）；`history --all` 也会读取所有页。加载更早的页面会保持阅读位置。

投影后的消息事件携带可选的 `originSeq`（原始显示顺序）和 `seq`（其最新合并的事件）。客户端增量归并实时事件，每 50 ms 批量提交可见更新，并缓存投影后的记录。页面合并会吸收直到页面游标的事件，并把更新的在途事件恰好重放一次。历史不得改变实时的会话/审批状态：快照优先于更早的元数据事件。Swift 从新快照和最近一页重连。仅请求的远程连接使用 `subscribe {after:"latest"}` 进行即时的加密健康校验；随后一个显式监听器从其请求的游标开始重放，涵盖快照/监听器竞态窗口。显式订阅保留事件顺序和游标，但超大文本返回预览，完整导出使用记录分块。回放分批让出事件循环，发送队列超限会断开而非无限堆积。

远程配置对相同的有效活动配置保持幂等。隧道失败按 1/2/4 秒退避自动重试，耗尽后等待显式重试；短暂连通不重置预算。固定域名保留配对，临时地址可能变化。现有 `online` 表示传输就绪，状态说明区分本地 Relay 就绪与设备最近确认的双向路径。运行时快照新增可选的 `busyKnown`，false 表示未知，不能证明空闲。SDK 提供关联方法与参数/结果的类型化调用，并按实际方法校验成功响应。

校验：`tests/history.test.ts` 覆盖 4,000 个 delta、完整工具对、向后游标边界、并发更新、本地/加密对等以及快照非回归。CLI/TUI 对等测试演练同一分页命令。`scripts/native-live-check.mjs` 为原生分页/导出/实时更新检查种下相同的长历史形状。`scripts/history-ui-check.mjs` 在 390 px 视口下演练加密浏览器分页、滚动锚定、完成和重新加载。浏览器自动化不是真实 iPhone/蜂窝网络测试。

Linux 安装可以运行可选的 `turnwire-host.service` supervisor（`apps/daemon/src/host-service.ts`）和 `bin/turnwire tui`。它启动同一个 daemon 与 DSH runtime；TUI 仍是客户端，SSH/TUI 退出不拥有主机生命周期。生成的服务路径派生自安装目录。每台主机保留自己的私有身份、状态和远程配对。不会授予额外的远程管理权限。

### 远程传输 v2 与通知

所有 TS 客户端共享 SDK 的分阶段连接生命周期，使用 `packages/wire` 提供的重试与会话加密原语。原生端仍为 Swift/SwiftUI，并使用相同的本地管理与 Core RPC。PWA 增加了浏览器特有的通知权限、Service Worker 展示以及可见性/在线提示；其收件箱和审批决定与 CLI/TUI/原生一样使用 Core。主机范围的通知管理仍仅限本地。远程用户只能订阅/退订自己的设备。

本地原生连接不会独立实现浏览器或 Relay 生命周期。其远程设置暴露直达 listener 配置、通知可用性/偏好、v2 配对/撤销以及设备 protocol/enrollment 状态（`pending` 或 `enrolled`），不提供凭据升级操作或 v1 兼容。手机通知投递使用模拟 provider 测试；实际的 iPhone 通知权限、锁屏投递和局域网证书接受需要设备测试。
