# 维护与不兼容状态拒绝指南

本文是最终操作规则，不是现场部署日志或预约重启记录。以下步骤不授权无人值守地改动活动主机、私有状态或凭据。

## 支持边界

- 配置、状态、运行时数据与缓存使用独立的 [XDG 目录](XDG.zh.md)，分别由 `TURNWIRE_CONFIG_HOME`、`TURNWIRE_STATE_HOME`、`TURNWIRE_DATA_HOME`、`TURNWIRE_CACHE_HOME` 覆盖。不识别旧布局。
- Store 只接受当前 schema（带持久化导出分片的存储版本 2）或全新数据库。旧版/不兼容数据库会被拒绝；不提供数据库迁移、导入或恢复旧数据的承诺。移动文件或改 schema 版本标记不能使其受支持。
- 远程配对仅支持 v2。旧配对不能原地升级。须通过经过认证的本地主机管理创建新邀请；邀请有效期 15 分钟，只可消耗一次。RPC/事件信封仍是 v1，不代表支持 v1 配对回退。
- TypeScript 客户端使用 SDK `call(method, params)`；共享加密与会话传输原语位于 `packages/wire`。远程设备不会获得主机维护权限。

## 任何维护之前

1. 安排外部维护窗口，停止新任务提交。检查受管会话、排队工作、所有层级子代理、独立 DSH 客户端及无关运行时会话。活动未知或查询失败不等于空闲。
2. 确认目标安装、服务、解析后的目录和发布产物，不打印 token 或环境变量值。不要覆盖其他安装的服务或客户端连接描述文件。
3. 妥善保存配置、Turnwire 状态与 DSH 状态/附件的一致备份。复制前停止写入进程，或使用合适的 SQLite 在线备份。不能只复制活动数据库主文件而忽略 WAL 一致性。保留原文件；备份不证明本版能兼容它。
4. 完整重启监督进程/DSH 会中断服务，也可能终止工作。不保证任务连续性，也不保证恢复旧会话。未经另行协调，不得重启承载当前 Agent 的服务。

## 当前 schema 下的 daemon 维护

只有满足前提时才使用[受控开发部署](SELF-HOSTING.zh.md)。`scripts/host-reload.sh --daemon --dry-run` 只暂存构建，不授予维护权限，也不证明运行时就绪。真正的 daemon-only 部署需要新鲜且经过认证的监督进程就绪记录，以及持有者拥有的持久本地维护租约。暂存 daemon 的 `--check-storage` 在取得维护租约之前，以及排空之后、安装之前分别校验兼容性；拒绝时不安装产物，也不发送重载信号。dry-run 仅构建，不读取活动数据库。就绪状态或受管活动未知时必须拒绝。构建后的 daemon 内嵌不可变构建 ID 和契约摘要；源码运行模式或不提供身份的旧健康响应不能用于发布验证。前端发布（包括显式 `--frontend`）必须匹配运行中的契约；daemon-only 发布还必须匹配当前提供的前端契约，并验证替换后的精确构建 ID。跨契约更新需要在外部协调完整发布，不能绕过这些检查。不能伪造就绪记录或修改租约来绕过拒绝。

租约阻止新的 Turnwire 变更，不限制独立 DSH 客户端。ready 租约跨 daemon 重启持久保留，直到显式释放。`turnwire maintenance compact` 清理可重建导出缓存并执行 SQLite 维护，不是数据库迁移，也不删除 journal/回执。监督进程、DSH 和依赖变更需要各自协调的完整维护窗口。

## 旧布局或数据库被拒绝时

停止尝试。私下保存原文件与拒绝诊断；不要换路径重试、篡改 schema 标记、删表或把旧库复制进 XDG 状态目录。本版没有自动转换或受支持的旧数据原地恢复流程。

操作者可以另外选择在空的、明确指定的目录中全新安装。这会创建新状态，需要重新配置主机并建立 v2 配对，不恢复旧身份、会话、回执或审批。调查旧版本自身的处理方案时，保持旧安装隔离且停止。仅回滚代码不能证明数据库或协议兼容。

## 验证与结果不确定

验证监督进程/daemon 身份、新鲜且经过认证的运行时就绪状态与本机 `/health`；再分别验证 Relay 注册、公网 HTTPS/WSS 可达性和真实配对设备的加密确认。单项绿色状态不能证明其他层都正常。仅对受支持的当前状态检查历史、待处理审批和命令回执。

遇到 `OUTCOME_UNKNOWN`，用 `turnwire result <request-id>` 查询原请求回执，不要重发变更来“试一下”。失败部署可能有意在持久租约下保持入口关闭。按开发指南中的持有者租约恢复流程检查实际健康状态，确认后才显式释放。构建成功不等于部署成功，更不等于服务无中断。

如实记录执行过的测试和未演练条件。Linux 文档检查不证明 macOS 编译、真实 iPhone 行为、推送投递或公网可用性。历史导出由隔离 worker 读取持久化分片，限制接纳数量、执行时间和记录大小；这不等于事件写入和预览也具有同样的全局内存上限。
