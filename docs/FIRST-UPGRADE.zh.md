## 外部维护窗口步骤

1. 结束本次 Agent 执行并停止新任务提交；检查全部托管会话、队列、所有层级子代理和独立 DSH 客户端。
2. 任一查询失败、任务仍在运行或状态不确定时停止操作；不要自动重试强制升级。
3. 保存当前恢复信息，保留状态目录和 DSH 状态目录，不更改模型列表或凭据。对数据库备份应使用 SQLite 在线备份或在完整停止之后复制，不能随意复制活动 WAL 主文件。
4. 从本机会话外的终端执行受控 `systemctl --user restart turnwire-dev.service`。这一次会停止 DSH，不能承诺原地无中断。
5. 检查监督进程和 daemon 存活、私有就绪记录新鲜且 ready、本机 `/health`、运行时认证以及公网固定域名和已配对设备的实际确认。
6. 检查会话历史、审批状态和命令回执；不得重发 outcome unknown 的变更命令来“试一下”。
7. 完成首次升级后，后续 daemon 更新才使用带持久维护租约的 `scripts/host-reload.sh --daemon`。监督进程或 DSH 本身的升级仍需完整维护窗口。

当前仅完成准备，没有安排自动重启作业。原生真实 HTTP 联调测试已提供，但普通 macOS CI 未启用需独立 daemon 的 opt-in 测试。SQLite 内部生成导出快照仍会物化实体，当前有界保证是 Node 侧分块读取，不是数据库引擎全程常量内存。
