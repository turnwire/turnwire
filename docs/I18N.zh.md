# 国际化

产品默认说英文，中文是第二语言。这一页记录**怎么切分**才能让两者不至于越走越远，以及三端共用的术语。

## 哪些共享，哪些不共享

- **共享：错误码。** `packages/protocol` 导出 `turnwireErrorCodes`，客户端按码渲染自己的句子。
  daemon 自己的消息固定是一条简短的**英文**兜底，所以 `--json` 的输出 —— 以及任何脚本解析的东西
  —— 不会随读者语言变化。宿主侧的用户可见文本一律英文，有测试强制这一点。
- **各端：用户可见文案。** PWA、CLI/TUI、原生 App 各自持有 `en` 与 `zh` 两份目录。三端媒介不同
  （行内小字、终端一行、原生弹窗），共享一句文案只会三头不讨好。
- **强制：完整性。** 每端都有测试断言：目录覆盖两种语言，且 `turnwireErrorCodes` 里的每个码都有
  文案。漏翻会让 CI 红，而不是悄悄在中文界面里露出英文。

当客户端数量超过几个、或文案量上到几千条时，回头看这一条：那时共享目录反而更省。今天的现实是
共享的是码（30 个）、各端的是散文（约 800 条）。

## 语言如何决定

| 客户端 | 探测 | 覆盖方式 |
| --- | --- | --- |
| PWA | `navigator.language` | 界面里的语言开关，持久化在 `localStorage` |
| CLI / TUI | `TURNWIRE_LANG`，其次 `LC_ALL` / `LANG` | `--lang en` 或 `--lang zh` |
| 原生 App | `Locale.current` | 通用设置，持久化在 `UserDefaults` |

`--json` 输出永远不本地化。
